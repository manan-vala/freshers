## 4. Vite Configuration

### `client/vite.config.ts`

```ts
import path from 'path'
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import { TanStackRouterVite } from '@tanstack/router-plugin/vite'

export default defineConfig({
  // DEPLOYMENT: VITE_BASE_URL is the nginx route prefix (e.g. /freshers-onboarding).
  // Empty in development. Set at Docker build time in production.
  // Vite bakes this into the built assets as the base path for all file references.
  base: process.env.VITE_BASE_URL ? `${process.env.VITE_BASE_URL}/` : '/',

  plugins: [
    TanStackRouterVite({ autoCodeSplitting: true }),
    react(),
  ],

  resolve: {
    alias: {
      '@': path.resolve(__dirname, './src'),
      '@shared': path.resolve(__dirname, '../shared'),
    },
  },

  server: {
    port: 3000,
    // DEV PROXY: In development, VITE_BASE_URL is empty so Axios baseURL is '/api'.
    // This proxy strips '/api' and forwards to the Express server.
    // Mirrors what nginx does in production with the /api/ location block.
    proxy: {
      '/api': {
        target: 'http://localhost:5000',
        changeOrigin: true,
        rewrite: (path) => path.replace(/^\/api/, ''),
      },
    },
  },
})
```

## 5. Tailwind CSS — Rules

### Setup

Tailwind v4 uses a CSS-first configuration. The **only** CSS file in the project is `src/index.css`:

```css
/* src/index.css — only CSS file that should exist */
@import "tailwindcss";
```

Import it once in `src/main.tsx`:

```ts
import './index.css'
```

### Rules for AI Agents — MANDATORY

- **NO additional CSS files.** Do not create `.css`, `.module.css`, or any other stylesheet.
- **NO `<style>` tags** in components.
- **NO inline `style={{}}` props** unless absolutely unavoidable (e.g., dynamic pixel values).
- **ALL styling must be done with Tailwind utility classes** directly in JSX `className` props.
- Use `cn()` (from `src/lib/utils.ts`, installed by shadcn) to conditionally merge classes:

```ts
import { cn } from '@/lib/utils'

<div className={cn('rounded-md p-4', isActive && 'bg-blue-50 border border-blue-200')} />
```

- For responsive design, use Tailwind breakpoint prefixes: `sm:`, `md:`, `lg:`.
- For dark mode (if enabled), use `dark:` prefix.
- Do **not** use Tailwind `@apply` in any CSS file.

## 7. TanStack Router

### File-Based Routing

Routes are files inside `src/routes/`. The `@tanstack/router-plugin` Vite plugin watches this directory and auto-generates `src/routeTree.gen.ts`. **Never edit `routeTree.gen.ts` manually.**

### Router Initialization (`src/main.tsx`)

```tsx
import { StrictMode } from 'react'
import ReactDOM from 'react-dom/client'
import { RouterProvider, createRouter } from '@tanstack/react-router'
import { QueryClientProvider } from '@tanstack/react-query'
import { routeTree } from './routeTree.gen'
import { queryClient } from './lib/queryClient'
import './index.css'

const router = createRouter({
  routeTree,
  // DEPLOYMENT: basepath must match the nginx deployment route.
  // In development this resolves to '/' (empty VITE_BASE_URL → fallback to '/').
  basepath: import.meta.env.VITE_BASE_URL || '/',
  context: { queryClient },
})

declare module '@tanstack/react-router' {
  interface Register {
    router: typeof router
  }
}

ReactDOM.createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <QueryClientProvider client={queryClient}>
      <RouterProvider router={router} />
    </QueryClientProvider>
  </StrictMode>
)
```

### Root Route — Auth Guard (`src/routes/__root.tsx`)

```tsx
import { createRootRouteWithContext, Outlet, redirect } from '@tanstack/react-router'
import type { QueryClient } from '@tanstack/react-query'
import { getCurrentUser } from '@/hooks/useAuth'

export const Route = createRootRouteWithContext<{ queryClient: QueryClient }>()({
  beforeLoad: async ({ location, context }) => {
    const user = await context.queryClient
      .fetchQuery({ queryKey: ['auth', 'me'], queryFn: getCurrentUser })
      .catch(() => null)

    const isAuthRoute = location.pathname === '/login'

    if (!user && !isAuthRoute) {
      throw redirect({ to: '/login' })
    }

    // FIRST-LOGIN GATE: block all routes except /change-password
    if (user?.mustChangePassword && location.pathname !== '/change-password') {
      throw redirect({ to: '/change-password' })
    }
  },
  component: () => <Outlet />,
})
```

### Navigation Rules

- Always use `<Link to="/path">` or `router.navigate({ to: '/path' })`.
- Never use `<a href="/path">` for internal links — this bypasses the basepath logic.
- Never use `window.location.href` for internal navigation.

## 8. TanStack Query

### QueryClient (`src/lib/queryClient.ts`)

```ts
import { QueryClient } from '@tanstack/react-query'

export const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 1000 * 60 * 5,    // 5 minutes — data is fresh
      gcTime: 1000 * 60 * 10,      // 10 minutes — keep in cache after unmount
      retry: 1,
      refetchOnWindowFocus: false,
    },
    mutations: {
      retry: 0,
    },
  },
})
```

### Query Key Conventions

```ts
// Always arrays. First element is the domain, second is the resource/id.
['auth', 'me']                         // current user
['student', 'onboarding', studentId]   // student's onboarding data
['allocation', allocationId]            // single allocation
['allocations', { hostelId, page }]    // list with filters
['rooms', hostelId]                    // rooms in a hostel
```

### Prefetching in Route Loaders

```ts
// src/routes/dashboard/student.tsx
export const Route = createFileRoute('/dashboard/student')({
  loader: ({ context: { queryClient } }) =>
    queryClient.ensureQueryData({
      queryKey: ['dashboard', 'student'],
      queryFn: () => api.get('/v1/dashboard/student').then(r => r.data.data),
    }),
  component: StudentDashboard,
```

## 9. API Client — Axios

### Setup (`src/lib/api.ts`)

```ts
import axios from 'axios'

// DEPLOYMENT:
// In development: VITE_BASE_URL is empty → baseURL = '/api'
//   → Vite proxy intercepts '/api/*' and rewrites to 'http://localhost:5000/*'
// In production: VITE_BASE_URL = '/freshers-onboarding' → baseURL = '/freshers-onboarding/api'
//   → nginx routes '/freshers-onboarding/api/*' to backend container, strips prefix
// In both cases, the backend Express server sees requests starting at '/v1/...'
const BASE_URL = `${import.meta.env.VITE_BASE_URL ?? ''}/api`

export const api = axios.create({
  baseURL: BASE_URL,
  withCredentials: true,   // Required — sends httpOnly auth cookies on every request
  headers: {
    'Content-Type': 'application/json',
  },
})

// 401 interceptor: attempt token refresh, then retry original request.
// If refresh fails, redirect to login.
let isRefreshing = false

api.interceptors.response.use(
  (res) => res,
  async (error) => {
    const original = error.config
    if (error.response?.status === 401 && !original._retry) {
      if (isRefreshing) return Promise.reject(error)
      original._retry = true
      isRefreshing = true
      try {
        await api.post('/v1/auth/refresh')
        isRefreshing = false
        return api(original)
      } catch {
        isRefreshing = false
        queryClient.clear()
        window.location.href = `${import.meta.env.VITE_BASE_URL ?? ''}/login`
        return Promise.reject(error)
      }
    }
    return Promise.reject(error)
  }
)
```

> **Import `{ api }` from `@/lib/api` everywhere.** Never create a second Axios instance. Never call `fetch()` directly for API requests.

### API Call Conventions

```ts
// Always call /v1/... — the /api prefix is handled by the proxy/nginx
const { data } = await api.get('/v1/dashboard/student')
await api.post('/v1/auth/login', { loginId, password })
await api.post('/v1/onboarding/submit', formData)
```

## 11. Forms — RHF + Zod

### Pattern

All forms use React Hook Form with the Zod resolver. Validation schemas are imported from `@shared/`. shadcn `<Form>` components are the layout layer.

```tsx
// src/components/forms/OnboardingForm.tsx
import { useForm } from 'react-hook-form'
import { zodResolver } from '@hookform/resolvers/zod'
import { useMutation } from '@tanstack/react-query'
import { onboardingSchema, type OnboardingInput } from '@shared/student'
import { api } from '@/lib/api'
import {
  Form, FormField, FormItem, FormLabel, FormControl, FormMessage,
} from '@/components/ui/form'
import { Input } from '@/components/ui/input'
import { Button } from '@/components/ui/button'

export function OnboardingForm() {
  const form = useForm<OnboardingInput>({
    resolver: zodResolver(onboardingSchema),
    defaultValues: {
      contactNumber: '',
      bloodGroup: undefined,
      // ...
    },
  })

  const submit = useMutation({
    mutationFn: (data: OnboardingInput) =>
      api.post('/v1/onboarding/submit', data),
    onSuccess: () => {
      // invalidate relevant queries
    },
  })

  return (
    <Form {...form}>
      <form
        onSubmit={form.handleSubmit((data) => submit.mutate(data))}
        className="space-y-6"
      >
        <FormField
          control={form.control}
          name="contactNumber"
          render={({ field }) => (
            <FormItem>
              <FormLabel>Contact Number</FormLabel>
              <FormControl>
                <Input placeholder="10-digit number" {...field} />
              </FormControl>
              <FormMessage />
            </FormItem>
          )}
        />
        <Button type="submit" disabled={submit.isPending}>
          {submit.isPending ? 'Submitting...' : 'Submit'}
        </Button>
      </form>
    </Form>
  )
}
```

### Rules

- Schema always comes from `@shared/` — never define validation logic in the component.
- Mutations always go through TanStack Query's `useMutation` — never call `api` directly in an event handler.
- Use `form.handleSubmit()` for submission — never use raw `onSubmit` without it.

## 12. Auth Flow & Route Guards

### `useAuth` Hook (`src/hooks/useAuth.ts`)

```ts
import { useQuery } from '@tanstack/react-query'
import { api } from '@/lib/api'

interface AuthUser {
  id: string
  role: 'STUDENT' | 'HMC' | 'ADMIN'
  mustChangePassword: boolean
}

export const getCurrentUser = async (): Promise<AuthUser> => {
  const { data } = await api.get('/v1/auth/me')
  return data.data
}

export function useAuth() {
  return useQuery({
    queryKey: ['auth', 'me'],
    queryFn: getCurrentUser,
    staleTime: Infinity,    // auth state doesn't go stale — invalidate manually on login/logout
    retry: false,
  })
}
```

### Role-Based Route Guard

Protect admin routes by checking role in `beforeLoad`:

```ts
// src/routes/admin/route.tsx
import { createFileRoute, redirect } from '@tanstack/react-router'
import { getCurrentUser } from '@/hooks/useAuth'

export const Route = createFileRoute('/admin')({
  beforeLoad: async ({ context }) => {
    const user = await context.queryClient.fetchQuery({
      queryKey: ['auth', 'me'],
      queryFn: getCurrentUser,
    })
    if (user.role !== 'ADMIN' && user.role !== 'HMC') {
      throw redirect({ to: '/dashboard/student' })
    }
  },
})
```

### Auth State Lifecycle

```
First visit / 401       → redirect to /login
Successful login        → server sets httpOnly cookies
  mustChangePassword    → redirect to /change-password (blocked until done)
  normal login          → redirect to /dashboard/student or /dashboard/admin
Password changed        → server invalidates session → redirect to /login
Logout                  → call POST /v1/auth/logout → clear queryClient → redirect to /login
```

## 13. Shared Schemas

Zod schemas in `shared/` are the single source of truth for both client-side form validation and server-side request validation. Import using the `@shared/` path alias:

```ts
import { onboardingSchema, type OnboardingInput } from '@shared/student'
import { loginSchema, type LoginInput } from '@shared/auth'
import { allocationSchema } from '@shared/allocation'
```

**Rules:**
- Never redefine a schema that already exists in `shared/`.
- If a new form field is needed, update the schema in `shared/` — not in the component.
- The Zod `z.infer<typeof schema>` type is the form's TypeScript type. Use it.

## 14. Deployment Configuration

### How the Deployment Works

```
Browser → domain.com/freshers-onboarding/login
  ↓
Outer nginx: location /freshers-onboarding/ → proxy_pass http://localhost:3000/
  (trailing slash in proxy_pass strips /freshers-onboarding prefix)
  ↓
Frontend container (port 3000) receives: /login
Inner nginx: try_files $uri $uri/ /index.html → serves index.html
  ↓
TanStack Router (basepath=/freshers-onboarding) handles /login route
```

```
Browser → domain.com/freshers-onboarding/api/v1/auth/login
  ↓
Outer nginx: location /freshers-onboarding/api/ → proxy_pass http://localhost:5000/
  ↓
Backend container (port 5000) receives: /v1/auth/login
```

### `VITE_BASE_URL` — The Single Source of Truth

| Context | Value | Effect |
|---|---|---|
| Development | `` (empty) | Vite base = `/`, router basepath = `/`, API baseURL = `/api` |
| Production build | `/freshers-onboarding` | Vite base = `/freshers-onboarding/`, router basepath = `/freshers-onboarding`, API baseURL = `/freshers-onboarding/api` |

### Dockerfile (`client/Dockerfile`)

```dockerfile
FROM node:24-alpine AS builder
WORKDIR /app

COPY package*.json ./
RUN npm ci

COPY . .

# VITE_BASE_URL is injected at build time — baked into the JS bundle
ARG VITE_BASE_URL=/freshers-onboarding
ENV VITE_BASE_URL=$VITE_BASE_URL

RUN npm run build

# Production: nginx serves the static bundle
FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

### Inner Nginx Config (`client/nginx.conf`)

This is the nginx config **inside the client container** — not the outer reverse proxy. Its only job is to serve the SPA and handle client-side routing:

```nginx
server {
    listen 80;
    root /usr/share/nginx/html;
    index index.html;

    # SPA fallback: all routes serve index.html
    # TanStack Router handles the actual routing in the browser
    location / {
        try_files $uri $uri/ /index.html;
    }

    # Cache static assets aggressively
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

### Rules for AI Agents — CRITICAL

- **Never hardcode** `/freshers-onboarding` or any deployment route in source code.
- **Never use** `window.location.href = '/some-path'` for internal navigation. Always use `router.navigate()` or `<Link>`.
- **Never call** the API with a hardcoded base URL. Always use the `api` instance from `@/lib/api`.
- When the user is redirected after login/logout, use `router.navigate()` — not `window.location`.
- The `VITE_BASE_URL` env var is available in source code as `import.meta.env.VITE_BASE_URL`. It is **not** available at runtime after build if not set at build time.
